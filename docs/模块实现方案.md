## 模块3：辩论室用户观点参与 + 本地 RAG 过滤

**优先级**：🔴 第一批，工作量约 4-5 天

### 设计思路

**交互优化**：不弹窗征集，直接复用现有弹幕输入框。Round1 结束后聊天区顶部出现轻提示条，用户正常发弹幕即参与观点征集，零额外操作。

**RAG 的作用**：不是评判观点好坏，不给用户贴标签。RAG 只做两件事：

1. **过滤灌水**：识别与辩论主题完全无关的内容（纯表情、刷屏、"哈哈哈"、"第一"），这类内容对辩论没有意义
2. **识别立场**：判断每条弹幕支持哪方（SUPPORT_A / SUPPORT_B / NEUTRAL），用于交叉注入

犀利的、情绪化的、极端的观点只要和主题相关，全部保留注入——这正是平台风格。用户完全感知不到过滤过程。

**注入方式**：把支持对方的观点交叉注入给己方 Bot 反驳，用户观点真正参与辩论。

### 新增 Python 微服务（opinion-service）

在 monorepo 根目录新增：

```
opinion-service/
├── main.py              # FastAPI 入口，暴露 HTTP 接口给 NestJS 调用
├── embedder.py          # Ollama 生成向量嵌入
├── relevance_checker.py # 相关性检测（与主题相关 vs 纯灌水）
├── stance_detector.py   # 立场识别（SUPPORT_A / SUPPORT_B / NEUTRAL）
├── deduplicator.py      # 语义去重（相似度>0.85合并为一条）
├── chroma_store.py      # ChromaDB 读写
├── requirements.txt
└── knowledge/           # 预构建知识库（启动时写入ChromaDB）
    ├── irrelevant.txt   # 灌水示例：哈哈/666/第一/纯表情/与话题无关
    └── relevant.txt     # 有效观点示例：各类风格均可，只要和主题沾边
```

**FastAPI 接口**：

| 方法 | 路径          | 说明                                   |
| ---- | ------------- | -------------------------------------- |
| POST | /process      | 处理单条弹幕，返回 isRelevant + stance |
| POST | /batch-filter | 批量处理，返回按立场分组的有效观点     |
| GET  | /health       | 健康检查                               |

**relevance_checker.py 核心逻辑**：

```python
def process_opinion(text: str, topic: str) -> dict:
    embedding = embedder.embed(text)

    # 1. 相关性检测：与灌水模板相似度高 → 过滤
    irrelevant_score = chroma_store.similarity(embedding, collection="irrelevant")
    is_relevant = irrelevant_score < 0.80  # 低于阈值才算有效

    # 2. 立场识别（仅对有效观点执行）
    stance = "NEUTRAL"
    if is_relevant:
        stance = stance_detector.detect(text, embedding)
        # SUPPORT_A / SUPPORT_B / NEUTRAL

    return { "isRelevant": is_relevant, "stance": stance }
```

**debate.service.ts 改造**：

```
原流程：
  runRound1() → runRound2() → runRound3() → broadcastVoteStart()

新流程：
  runRound1()                          // BotA、BotB 并发陈述立场
    → broadcastOpinionCollectStart()   // 广播：开启60秒征集，聊天区显示提示条
    → 期间：用户发弹幕
        → 正常写入Message表（弹幕照常显示）
        → 异步调RAG微服务判断 isRelevant + stance
        → 写入UserOpinion表
    → sleep(60000)
    → broadcastOpinionCollectEnd()     // 广播：征集结束，显示有效观点数量
    → groupOpinionsByStance(roomId)    // 按立场分组，过滤掉 isRelevant=false
    → runRound2(opinionsForA, opinionsForB)
    → runRound3(allOpinionsSummary)
    → broadcastVoteStart()
```

**分组逻辑**：

```typescript
async groupOpinionsByStance(roomId: number) {
  const opinions = await prisma.userOpinion.findMany({
    where: { roomId, isRelevant: true }  // 只取有效观点
  });

  // 语义去重后按立场分组，每组最多5条（按时间顺序，先来先得）
  const deduped = await this.deduplicateBySemantics(opinions);

  return {
    forA: deduped.filter(o => o.stance === 'SUPPORT_A').slice(0, 5),
    forB: deduped.filter(o => o.stance === 'SUPPORT_B').slice(0, 5),
    neutral: deduped.filter(o => o.stance === 'NEUTRAL').slice(0, 3),
  };
}
```

**WebSocket 新增事件**：

| 事件名                | 方向          | 说明                             |
| --------------------- | ------------- | -------------------------------- |
| `opinionCollectStart` | Server→Client | 广播开始征集，携带倒计时秒数     |
| `opinionCollectEnd`   | Server→Client | 广播结束，携带各立场有效观点数量 |

> 提交观点复用现有弹幕接口，征集窗口期间后端自动标记 `isOpinion=true`，前端无感知。

### RAG 四层架构总结（论文亮点）

| 层次       | 用途                                 | 类型             | 技术                       |
| ---------- | ------------------------------------ | ---------------- | -------------------------- |
| 第一层     | 智能体专业知识（博弈论/心理学/法律） | 静态云端 RAG     | Coze 云端 RAG              |
| 第二层     | 用户私有知识库（上传文档）           | 静态云端 RAG     | Coze 云端 RAG              |
| 第三层     | 用户弹幕观点相关性过滤与立场识别     | 本地静态 RAG     | 本地 ChromaDB + Ollama     |
| **第四层** | **用户个人情绪历史记忆（动态）**     | **本地动态 RAG** | **本地 ChromaDB + Ollama** |

第四层是真正的**动态个性化 RAG**：知识库内容随用户每次辅导会话持续增长，检索时按当前话题语义匹配最相关的历史片段，而非简单堆砌全部历史。论文中可将"静态RAG vs 动态RAG"作为对比分析点单独成节。

## 模块4：心理辅导（共情辅导师 + 个性化情绪记忆图谱）

**优先级**：🟡 第二批，工作量约 4-5 天

### 体验目标

类似 ChatGPT 的持续对话体验，辅导师通过动态 RAG 记忆越聊越懂用户，同时维护一份个性化情绪档案，根据用户的情绪模式、核心话题、应对偏好动态调整辅导风格。

### Coze 配置

新建共情辅导师 Bot，挂载心理学知识库（静态 RAG）：

- 《认知行为疗法（CBT）实用指南》
- 《非暴力沟通》
- 《焦虑情绪管理手册》

System Prompt 核心要求：

- 共情优先，先认可情绪再给建议
- 避免说教，以提问引导用户自我探索
- 根据用户应对偏好调整风格（倾听型 vs 建议型，感性 vs 理性）
- 如携带案件上下文，主动引用辩论结论

**System Prompt 动态拼接逻辑**：

```typescript
async buildSystemPrompt(userId: number, sessionId: number): Promise<string> {
  const session = await prisma.counselingSession.findUnique({ where: { id: sessionId } });
  let prompt = BASE_COUNSELOR_PROMPT;

  // 1. 注入情绪档案（结构化，直接读数据库）
  const profile = await prisma.userEmotionProfile.findUnique({ where: { userId } });
  if (profile && profile.sessionCount > 0) {
    prompt += `\n\n【用户情绪档案】\n`;
    prompt += `近期主导情绪：${profile.dominantEmotion}，趋势：${profile.emotionTrend}\n`;
    prompt += `核心困扰话题：${profile.coreTopics}\n`;
    prompt += `应对偏好：${profile.preferListening ? '倾向被倾听' : '倾向获得建议'}，`;
    prompt += `${profile.preferRational ? '倾向理性分析' : '倾向情感共鸣'}\n`;
    prompt += `请根据用户偏好调整你的辅导风格。`;
  } else {
    // 初次用户：温暖引导式开场
    prompt += `
这是用户第一次使用心理辅导功能。
请用温暖友好的方式自我介绍，用开放式问题引导用户开口。
不要显得过于正式或像心理测评问卷。
    `;
  }

  // 2. 动态 RAG：根据当前话题语义检索最相关的历史记忆
  // （非简单堆砌全部历史，而是按相关性检索，控制 Prompt 长度）
  if (profile && profile.sessionCount > 0) {
    const currentTopic = session.title || '最近的烦恼';
    const relevantMemories = await this.chromaService.searchUserMemories(
      userId, currentTopic, { limit: 3 }
    );
    if (relevantMemories.length > 0) {
      prompt += `\n\n【与本次话题相关的历史记忆（RAG检索）】\n`;
      relevantMemories.forEach(m => {
        prompt += `- ${m.date}：${m.summary}\n`;
      });
      prompt += `请在适当时机自然引用，不要生硬列举。`;
    }
  }

  // 3. 若关联案件，拼接辩论上下文
  if (session.roomId) {
    const room = await prisma.room.findUnique({ where: { id: session.roomId } });
    const report = await this.roomsService.getReport(session.roomId);
    prompt += `\n\n【本次关联的用户困境】\n`;
    prompt += `困境描述：${room.content}\n`;
    prompt += `AI辩论结论：${report.summary}\n`;
    prompt += `请结合以上背景给予针对性疏导，无需用户重复描述。`;
  }

  // 4. 若关联情感测评，拼接测评结果
  if (session.sentimentRecordId) {
    const record = await prisma.sentimentRecord.findUnique({ where: { id: session.sentimentRecordId } });
    prompt += `\n\n【用户当前情绪状态（来自情感测评）】\n`;
    prompt += `情绪类型：${record.emotionType}，强度：${record.intensity}/100，关键词：${record.keywords}\n`;
    prompt += `请以此为切入点开始对话。`;
  }

  return prompt;
}
```

**会话结束后的异步处理**（三件事并行，不阻塞用户）：

```typescript
async closeSession(sessionId: number) {
  await prisma.counselingSession.update({
    where: { id: sessionId },
    data: { status: 'CLOSED' }
  });

  // 三件事异步并行执行，立即返回前端
  Promise.all([
    this.generateSummaryAndVectorize(sessionId),  // 生成摘要 + 向量化存ChromaDB
    this.updateEmotionProfile(sessionId),          // 更新情绪档案
  ]).catch(err => console.error('会话归档失败', err));

  return { success: true };
}

private async generateSummaryAndVectorize(sessionId: number) {
  const session = await prisma.counselingSession.findUnique({
    where: { id: sessionId },
    include: { messages: { orderBy: { createdAt: 'asc' } } }
  });
  // 1. 调 Coze 生成摘要：[情绪类型] + 一句话核心事件
  const summary = await this.cozeService.summarizeSession(session.messages);
  await prisma.counselingSession.update({ where: { id: sessionId }, data: { summary } });

  // 2. 向量化摘要，存入该用户的 ChromaDB 集合（动态RAG知识库）
  await this.chromaService.addUserMemory(session.userId, {
    sessionId, summary, date: new Date().toLocaleDateString()
  });
}

private async updateEmotionProfile(sessionId: number) {
  // 调 Coze 分析本次会话，提取：主导情绪、话题关键词、应对偏好信号
  // 更新 UserEmotionProfile 表（upsert）
  const analysis = await this.cozeService.analyzeSessionProfile(sessionId);
  await prisma.userEmotionProfile.upsert({
    where: { userId: analysis.userId },
    update: {
      dominantEmotion: analysis.dominantEmotion,
      emotionTrend: analysis.trend,
      coreTopics: JSON.stringify(analysis.topics),
      sessionCount: { increment: 1 }
    },
    create: { userId: analysis.userId, ...analysis }
  });
}
```

```typescript
async checkAndUnlock(userId: number, achievementName: string) {
  const achievement = await prisma.achievement.findUnique({ where: { name: achievementName } });
  const user = await prisma.user.findUnique({ where: { id: userId } });
  const unlocked = JSON.parse(user.achievements || '[]');
  if (!unlocked.includes(achievement.id)) {
    unlocked.push(achievement.id);
    await prisma.user.update({
      where: { id: userId },
      data: {
        achievements: JSON.stringify(unlocked),
        exp: { increment: achievement.expReward },
        level: this.calcLevel(user.exp + achievement.expReward)
      }
    });
    // 推送通知
    await this.notificationsService.create({ userId, type: 'ACHIEVEMENT_UNLOCKED', ... });
  }
}
```
