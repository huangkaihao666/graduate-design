## 模块3：辩论室用户观点参与

**优先级**：🔴 第一批，工作量约 3-4 天

### 设计思路

参考真实辩论赛流程：用户观点在 Round1 结束后征集（此时用户刚看完两方立场，最有发言欲）。注入方式不是"让 Bot 参考用户观点"，而是**把支持对方的用户观点作为反驳素材传给己方 Bot**，Bot 需要正面回应这些观点，用户观点真正参与辩论而不是走过场。

### 后端实现

**debate.service.ts 改造**（核心改动）：

```
原流程：
  runRound1() → runRound2() → runRound3() → broadcastVoteStart()

新流程：
  runRound1()                          // BotA、BotB 并发陈述立场
    → broadcastOpinionCollectStart()   // 广播：开启60秒用户观点征集
    → sleep(60000)                     // 等待用户提交并点赞
    → broadcastOpinionCollectEnd()     // 广播：征集结束
    → getOpinionsByStance(roomId)      // 按立场分组取 Top3
    → runRound2(opinionsForA, opinionsForB)  // 交叉注入
    → runRound3(allOpinionsSummary)    // BotC 引用观众倾向
    → broadcastVoteStart()
```

**Prompt 注入模板**（Round2，交叉注入）：

```typescript
// BotA 的 Round2 Prompt（注入支持 BotB 的用户观点，让 BotA 反驳）
`以下是部分观众支持对方（BotB）的理由，请在反驳中正面回应这些观点：
1. "${opinionsForB[0].content}"（${opinionsForB[0].likeCount}人赞同）
2. "${opinionsForB[1].content}"（${opinionsForB[1].likeCount}人赞同）
3. "${opinionsForB[2].content}"（${opinionsForB[2].likeCount}人赞同）`;

// BotB 的 Round2 Prompt 同理，注入支持 BotA 的观点
```

**Prompt 注入模板**（Round3，BotC 裁决引用观众倾向）：

```typescript
`【观众观点分布】
支持 ${botAName} 方向的观众观点（共${countA}条）：
${topOpinionsForA.map((o) => `- "${o.content}"`).join("\n")}

支持 ${botBName} 方向的观众观点（共${countB}条）：
${topOpinionsForB.map((o) => `- "${o.content}"`).join("\n")}

请在裁决时综合考虑观众倾向，可适当引用"有X位观众认为..."。`;
```

**用户观点按立场分组**：`UserOpinion` 表新增 `stance` 字段（SUPPORT_A / SUPPORT_B / NEUTRAL），用户提交观点时选择立场。

**新增接口**：

| 方法   | 路径                          | 说明                           | 权限 |
| ------ | ----------------------------- | ------------------------------ | ---- |
| POST   | /rooms/:id/opinions           | 提交用户观点（含 stance 字段） | 登录 |
| POST   | /rooms/:id/opinions/:oid/like | 为观点点赞                     | 登录 |
| DELETE | /rooms/:id/opinions/:oid/like | 取消点赞                       | 登录 |
| GET    | /rooms/:id/opinions           | 获取观点列表（按点赞排序）     | 公开 |

**WebSocket 新增事件**：

| 事件名                | 方向          | 说明                                 |
| --------------------- | ------------- | ------------------------------------ |
| `opinionCollectStart` | Server→Client | 广播开始征集，携带倒计时秒数（60）   |
| `opinionCollectEnd`   | Server→Client | 广播征集结束，携带已采纳的 Top3 观点 |
| `opinionUpdate`       | Server→Client | 有人提交/点赞时广播最新观点列表      |

### 前端实现

1. **辩论室**（`debate-room/DebateRoom.tsx`）：
   - 监听 `opinionCollectStart`：在辩论舞台区弹出观点征集面板（60秒倒计时进度条）
   - 面板布局：
     ```
     ┌─────────────────────────────────────┐
     │  💬 你支持哪方？说说你的理由          │
     │  ○ 支持 BotA  ○ 支持 BotB  ○ 中立  │
     │  ┌─────────────────────────────┐    │
     │  │ 输入你的观点（最多100字）...  │    │
     │  └─────────────────────────────┘    │
     │  [提交观点]          剩余 42 秒      │
     │  ─────────────────────────────────  │
     │  当前热门观点：                      │
     │  👍23  "BotA说的更现实..." [点赞]   │
     │  👍18  "感情的事不能只看利益" [点赞] │
     └─────────────────────────────────────┘
     ```
   - 监听 `opinionUpdate` 实时更新热门观点排序
   - 监听 `opinionCollectEnd`：关闭面板，在舞台区显示"已采纳 Top3 观点，注入第二轮辩论"提示条，展示被采纳的观点内容

## 模块5：心理辅导（共情辅导师）

**优先级**：🟡 第二批，工作量约 3-4 天

### 体验目标

类似 ChatGPT 的持续对话体验：左侧会话列表 + 右侧聊天区，可以随时打开聊、随时切换历史对话，辅导师有跨会话记忆，越聊越懂用户。

### Coze 配置

新建共情辅导师 Bot，挂载心理学知识库：

- 《认知行为疗法（CBT）实用指南》
- 《非暴力沟通》
- 《焦虑情绪管理手册》

System Prompt 核心要求：

- 共情优先，先认可情绪再给建议
- 避免说教，以提问引导用户自我探索
- 如携带案件上下文，主动引用辩论结论
- 如携带历史情绪小结，在新会话开场时主动关心

### 后端实现

**新建模块** `src/modules/counseling/`

**接口列表**：

| 方法   | 路径                              | 说明                                            | 权限 |
| ------ | --------------------------------- | ----------------------------------------------- | ---- |
| POST   | /counseling/sessions              | 创建新会话（可携带 roomId / sentimentRecordId） | 登录 |
| GET    | /counseling/sessions              | 获取历史会话列表（分页）                        | 登录 |
| GET    | /counseling/sessions/:id/messages | 获取会话完整消息历史                            | 登录 |

**System Prompt 动态拼接逻辑**：

> 实现原理：**不是 RAG**，而是 Prompt 注入（Context Injection）。
> 从数据库直接查结构化数据拼接到 System Prompt，无额外向量检索开销。
> RAG 只用于辅导师的心理学专业知识库（CBT/非暴力沟通）。

```typescript
async buildSystemPrompt(userId: number, sessionId: number): Promise<string> {
  const session = await prisma.counselingSession.findUnique({ where: { id: sessionId } });

  // 1. 基础共情人格 Prompt
  let prompt = BASE_COUNSELOR_PROMPT;

  // 2. 判断是否初次用户，分支处理
  const recentSessions = await prisma.counselingSession.findMany({
    where: { userId, id: { not: sessionId }, summary: { not: null } },
    orderBy: { createdAt: 'desc' },
    take: 5,
    select: { summary: true, createdAt: true }
  });

  if (recentSessions.length === 0) {
    // 初次用户：引导式开场，不要显得正式
    prompt += `
这是用户第一次使用心理辅导功能。
请用温暖友好的方式自我介绍，告诉用户可以随时倾诉任何烦恼，
然后用一个开放式问题引导用户开口，例如"最近有什么让你感到困扰的事吗？"
不要显得过于正式或像心理测评问卷。
    `;
  } else {
    // 老用户：注入历史摘要，跨会话记忆
    // 注意：summary 在会话结束时异步生成并存库，此处直接读取，0延迟
    prompt += `\n\n【用户近期情绪记录】\n`;
    recentSessions.forEach(s => {
      prompt += `- ${s.createdAt.toLocaleDateString()}：${s.summary}\n`;
    });
    prompt += `请在适当时机自然地关心用户近期状态，不要生硬地逐条列举。`;
  }

  // 3. 若关联案件，拼接辩论上下文
  if (session.roomId) {
    const room = await prisma.room.findUnique({ where: { id: session.roomId } });
    const report = await this.roomsService.getReport(session.roomId);
    prompt += `\n\n【本次关联的用户困境】\n`;
    prompt += `困境描述：${room.content}\n`;
    prompt += `AI辩论结论摘要：${report.summary}\n`;
    prompt += `请结合以上背景，给予针对性的情绪疏导，无需用户重复描述。`;
  }

  // 4. 若关联情感测评，拼接测评结果
  if (session.sentimentRecordId) {
    const record = await prisma.sentimentRecord.findUnique({ where: { id: session.sentimentRecordId } });
    prompt += `\n\n【用户当前情绪状态（来自情感测评）】\n`;
    prompt += `情绪类型：${record.emotionType}，强度：${record.intensity}/100\n`;
    prompt += `关键词：${record.keywords}\n`;
    prompt += `请以此为切入点开始对话。`;
  }

  return prompt;
}
```

**消息历史传递**：每次调用 Coze API 时，将当前会话的完整消息历史作为 `additional_messages` 传入，保证对话连贯性。

**summary 异步生成（关键：不阻塞用户）**：

```typescript
// 会话关闭时立即返回，summary 在后台异步生成，不让用户等待
async closeSession(sessionId: number) {
  await prisma.counselingSession.update({
    where: { id: sessionId },
    data: { status: 'CLOSED' }
  });

  // 异步生成，不 await，失败只记日志不影响主流程
  this.generateSummaryAsync(sessionId).catch(err =>
    console.error('summary 生成失败', err)
  );

  return { success: true }; // 立即返回前端
}

private async generateSummaryAsync(sessionId: number) {
  const messages = await prisma.counselingMessage.findMany({
    where: { sessionId },
    orderBy: { createdAt: 'asc' }
  });
  // 调 Coze，要求输出格式：[情绪类型] + 一句话核心事件描述
  // 例："焦虑，用户因室友长期占用公共空间感到压抑，最终决定直接沟通"
  const summary = await this.cozeService.summarizeSession(messages);
  await prisma.counselingSession.update({
    where: { id: sessionId },
    data: { summary }
  });
}
```

**自动归档**：NestJS 定时任务（`@Cron('0 * * * *')`），每小时检查超过 30 分钟无新消息的进行中会话，自动触发 `closeSession`。

SELECT r.* FROM rooms r

**成就解锁逻辑**：

```typescript
async checkAndUnlock(userId: number, achievementName: string) {
  const achievement = await prisma.achievement.findUnique({ where: { name: achievementName } });
  const user = await prisma.user.findUnique({ where: { id: userId } });
  const unlocked = JSON.parse(user.achievements || '[]');
  if (!unlocked.includes(achievement.id)) {
    unlocked.push(achievement.id);
    await prisma.user.update({
      where: { id: userId },
      data: {
        achievements: JSON.stringify(unlocked),
        exp: { increment: achievement.expReward },
        level: this.calcLevel(user.exp + achievement.expReward)
      }
    });
    // 推送通知
    await this.notificationsService.create({ userId, type: 'ACHIEVEMENT_UNLOCKED', ... });
  }
}
```
