## 模块3：辩论室用户观点参与 + 本地 RAG 过滤

**优先级**：🔴 第一批，工作量约 4-5 天

### 设计思路

**交互优化**：不弹窗征集，直接复用现有弹幕输入框。Round1 结束后聊天区顶部出现轻提示条，**显示双方智能体名字**（如"支持「毒舌现实主义者」还是「温柔共情者」？说出你的理由"），引导用户明确表态，用户正常发弹幕即参与观点征集，零额外操作。

**RAG 的核心职责**：**过滤灌水**，不强依赖立场识别。

1. **过滤灌水**：识别与辩论主题完全无关的内容（纯表情、刷屏、"哈哈哈"、"第一"），这类内容对辩论没有意义
2. **语义去重**：合并语义高度相似的重复观点，避免同一观点反复注入
3. **立场识别（参考用）**：判断每条弹幕的立场倾向（SUPPORT_A / SUPPORT_B / NEUTRAL），写入数据库供统计展示，**不作为 prompt 注入的分配依据**

犀利的、情绪化的、极端的观点只要和主题相关，全部保留注入——这正是平台风格。用户完全感知不到过滤过程。

**注入方式**：过滤后的全量有效观点（最多20条）同时注入给两个 Bot，prompt 说明"观点来自真实用户，立场未预先标注，请自行判断哪些支持你的立场，自然引用 1-2 条"。让智能体自己读懂观众的声音，比系统预先贴标签更准确、更自然。

**立场识别双轨策略**（仅用于数据库记录）：

- 关键词规则（优先）：文本含智能体名字 + 支持/反对词时直接判定
- 动态语义锚点（兜底）：基于本场辩论的智能体名字实时生成锚点向量，余弦相似度差值 > 0.05 才判定立场，否则 NEUTRAL

### 新增 Python 微服务（opinion-service）

在 monorepo 根目录新增，同时服务第三层（弹幕过滤）和第四层（情绪记忆）：

```
opinion-service/
├── main.py              # FastAPI 入口，暴露 HTTP 接口给 NestJS 调用
├── embedder.py          # Ollama 生成向量嵌入（两层共用，启动时 dummy embed 预热）
├── relevance_checker.py # 第三层：相关性检测（与主题相关 vs 纯灌水）
├── stance_detector.py   # 第三层：立场识别（SUPPORT_A / SUPPORT_B / NEUTRAL）
├── deduplicator.py      # 第三层：语义去重（相似度>0.85合并为一条）
├── memory_store.py      # 第四层：用户情绪记忆存取
├── chroma_store.py      # ChromaDB 读写（两层共用）
├── requirements.txt
└── knowledge/           # 第三层预构建知识库（启动时写入ChromaDB）
    ├── irrelevant.txt   # 灌水示例：哈哈/666/第一/纯表情/与话题无关
    └── relevant.txt     # 有效观点示例：各类风格均可，只要和主题沾边
```

**FastAPI 接口总览**：

| 方法 | 路径             | 说明                                                                    | 服务层次 |
| ---- | ---------------- | ----------------------------------------------------------------------- | -------- |
| POST | /process         | 处理单条弹幕，返回 isRelevant + stance（接收 agentAName/agentBName）    | 第三层   |
| POST | /batch-filter    | 批量处理弹幕，返回 valid（全量有效）+ forA/forB/neutral（立场分组参考） | 第三层   |
| POST | /memories/add    | 向量化会话摘要，存入用户专属 ChromaDB 集合                              | 第四层   |
| POST | /memories/search | 以文本 query 检索最相关历史摘要，返回摘要文本列表                       | 第四层   |
| GET  | /health          | 健康检查                                                                | 通用     |

**ChromaDB 数据结构（第四层）**：

每条记忆存三个字段，检索命中后直接把摘要文本拼入 prompt，无需回查数据库：

```
向量（embedding）  ← 由摘要文本计算，用于相似度检索
文本（document）   ← 摘要原文（如"用户因考研焦虑，倾向被倾听"），命中后直接注入 prompt
元数据（metadata） ← { sessionId, date, userId }
```

**relevance_checker.py 核心逻辑**：

```python
# 相关性阈值：与灌水示例相似度超过 0.55 视为灌水（exp(-dist/50) 转换）
IRRELEVANT_THRESHOLD = 0.55
MIN_LENGTH = 3          # 少于3字直接视为灌水
REPEAT_CHAR_RATIO = 0.6 # 单字符占比超过60%视为重复刷屏

def process(text: str) -> dict:
    # 规则兜底（超短/重复字符）
    if _is_spam_by_rule(text):
        return { "isRelevant": False, "embedding": embedder.embed(text) }
    # 向量相似度检测
    vec = embedder.embed(text)
    score = chroma_store.max_similarity("irrelevant", vec)
    return { "isRelevant": score < IRRELEVANT_THRESHOLD, "embedding": vec }
```

**stance_detector.py 双轨策略**：

```python
def detect(embedding, topic="", agent_a_name="", agent_b_name="", text="") -> str:
    # 第一轨：关键词规则（高精度，优先）
    # 文本含智能体名字 + 支持/反对词 → 直接判定
    if text and agent_a_name and agent_b_name:
        kw_result = _keyword_stance(text, agent_a_name, agent_b_name)
        if kw_result: return kw_result

    # 第二轨：动态语义锚点（余弦相似度）
    # 锚点 = 多句"我支持{name}，{name}说得对"拼接段落，覆盖多种表达方式
    # 锚点按 topic+名字 缓存，同一场辩论只生成一次
    vec_a, vec_b = _get_anchors(topic, agent_a_name, agent_b_name)
    score_a = _cosine_sim(embedding, vec_a)
    score_b = _cosine_sim(embedding, vec_b)
    diff = abs(score_a - score_b)
    if diff < DIFF_THRESHOLD:  # 0.05
        return "NEUTRAL"
    return "SUPPORT_A" if score_a > score_b else "SUPPORT_B"
```

### RAG 四层架构总结（论文亮点）

| 层次       | 用途                                 | 类型             | 技术                       | 核心设计点                                        |
| ---------- | ------------------------------------ | ---------------- | -------------------------- | ------------------------------------------------- |
| 第一层     | 智能体专业知识（博弈论/心理学/法律） | 静态云端 RAG     | Coze 云端 RAG              | 云端托管，零运维                                  |
| 第二层     | 用户私有知识库（上传文档）           | 静态云端 RAG     | Coze 云端 RAG              | 用户上传，动态绑定                                |
| 第三层     | 弹幕灌水过滤（立场识别参考）         | 本地静态 RAG     | 本地 ChromaDB + Ollama     | 只过滤灌水，全量有效观点注入，立场由 LLM 自行判断 |
| **第四层** | **用户个人情绪历史记忆（动态）**     | **本地动态 RAG** | **本地 ChromaDB + Ollama** | 预检索缓存消除延迟，摘要注入最后一条消息前        |

**第三层设计决策**：早期设计将立场识别结果作为分配依据（支持A的观点给B反驳），但实测发现 `nomic-embed-text` 对中文人名语义区分度不足，误判率较高。最终改为：RAG 只负责过滤灌水，全量有效观点注入 prompt，由 LLM 自行判断立场。这一设计更鲁棒，换任何辩题都适用。

**第四层是真正的动态个性化 RAG**：知识库内容随用户每次辅导会话持续增长，检索时按当前话题语义匹配最相关的历史片段，而非简单堆砌全部历史。论文中可将"静态RAG vs 动态RAG"、"云端RAG vs 本地RAG"作为对比分析点单独成节。

## 模块4：心理辅导（共情辅导师 + 个性化情绪记忆图谱）

**优先级**：🟡 第二批，工作量约 4-5 天

### 体验目标

类似 ChatGPT 的持续对话体验，辅导师通过动态 RAG 记忆越聊越懂用户，同时维护一份个性化情绪档案，根据用户的情绪模式、核心话题、应对偏好动态调整辅导风格。

### Coze 配置

新建共情辅导师 Bot，挂载心理学知识库（静态 RAG）：

- 《认知行为疗法（CBT）实用指南》
- 《非暴力沟通》
- 《焦虑情绪管理手册》

System Prompt 核心要求：

- 共情优先，先认可情绪再给建议
- 避免说教，以提问引导用户自我探索
- 根据用户应对偏好调整风格（倾听型 vs 建议型，感性 vs 理性）
- 如携带案件上下文，主动引用辩论结论

**System Prompt 动态拼接逻辑（实际实现）**：

RAG 记忆不拼在 system prompt 里，而是**注入最后一条用户消息前**，确保模型生成回复时记忆就在当前消息旁边，参考效果最好。

```typescript
// buildSystemExtra：构建注入内容（案件上下文 + RAG历史记忆）
async buildSystemExtra(session: any, cachedMemories: string[]): Promise<string> {
  const parts: string[] = [];

  // 1. 注入 RAG 检索到的历史记忆
  if (cachedMemories.length > 0) {
    parts.push(
      '【背景参考：以下是该用户在过去几次对话中留下的核心情绪记录】\n' +
      cachedMemories.map((m, i) => `${i + 1}. ${m}`).join('\n') +
      '\n\n【使用指引】\n' +
      '- 这些是用户真实经历过的事，回复时可自然提及，例如"你之前提到……"\n' +
      '- 如果当前话题与某条记录有关联，主动把两者联系起来\n' +
      '- 选最相关的 1-2 条自然融入，不要一次性列举所有\n' +
      '- 语气要温暖自然，像一个真正记得用户的朋友'
    );
  }

  // 2. 若关联案件，注入辩论上下文
  if (session.roomId) {
    const room = await prisma.room.findUnique({ where: { id: session.roomId } });
    if (room) {
      parts.push(
        `【用户关联的困境案件】\n案件标题：${room.title}\n案件描述：${room.content}\n` +
        `请结合以上背景给予针对性疏导，无需用户重复描述背景。`
      );
    }
  }

  return parts.join('\n\n');
}

// streamCounselorChat：注入位置在最后一条用户消息前
const lastUserIdx = history.map(m => m.role).lastIndexOf('user');
const messages = history.map((m, i) => ({
  role: m.role,
  content: i === lastUserIdx && systemExtra
    ? `${systemExtra}\n\n用户当前消息：${m.content}`
    : m.content,
  content_type: 'text',
}));
```

**预检索缓存（消除 Ollama 嵌入延迟）**：

```typescript
// 内存 Map 缓存预检索结果，key = sessionId，value = 摘要文本列表（格式："日期：摘要"）
private prefetchCache = new Map<string, string[]>();

// 前端 onChange 防抖 300ms 后调用此接口
async prefetchMemories(sessionId: number, userId: number, inputText: string) {
  if (!inputText.trim()) return;
  const memories = await this.ragService.searchMemories(userId, inputText, 3);
  this.prefetchCache.set(`${sessionId}`, memories);
}

// sendMessage 中读取缓存，用完即清（避免下一条消息误用）
async sendMessage(sessionId: number, userId: number, content: string, res: Response) {
  const cachedMemories = this.prefetchCache.get(`${sessionId}`) ?? [];
  this.prefetchCache.delete(`${sessionId}`);
  const systemExtra = await this.buildSystemExtra(session, cachedMemories);
  await this.cozeService.streamCounselorChat(COUNSELOR_BOT_ID, history, systemExtra, onChunk);
}
```

**会话归档流程（实际实现）**：

```typescript
// 会话关闭时异步归档（不阻塞用户）
private async archiveSession(sessionId: number, userId: number) {
  const messages = await prisma.counselingMessage.findMany({
    where: { sessionId }, orderBy: { createdAt: 'asc' }
  });
  if (messages.length < 2) return; // 对话太短不归档

  // 1. 调 Coze 生成一句话摘要：格式 "[情绪类型] 核心事件"
  //    例："[焦虑] 考研压力大，倾向被倾听而非获得建议"
  const summary = await this.cozeService.summarizeSession(messages);
  if (!summary) return;

  // 2. 写回数据库
  await prisma.counselingSession.update({ where: { id: sessionId }, data: { summary } });

  // 3. 向量化摘要，存入用户专属 ChromaDB 集合
  const date = new Date().toISOString().slice(0, 10);
  await this.ragService.addMemory({ userId, sessionId, summary, date });
}
```

**自动归档触发时机（两种）**：

- `@Cron('*/5 * * * *')` 每5分钟扫描，超过5分钟无消息的 ACTIVE 会话自动关闭并归档
- 新建会话时异步归档上一个 ACTIVE 会话，两者互不阻塞

## 模块5：情绪洞察中心（原"情感分析"，已调整）

> **调整说明**：原方案是独立的单次分析工具，现在升级为**情绪洞察中心**，聚合用户在平台上的所有行为数据，形成持续积累、可回看趋势的情感画像。

### 三路数据源设计

| -------------- | ---------------------------- | ------------------ | ------------------- |
| 用户发布的案件 | `Room.sentimentType`         | 遇到了什么困境     | 本模块完成后        |
| 手动情感测评   | `SentimentRecord`            | 当下的主动情绪输入 | 本模块完成后        |
| AI 共情师会话  | `CounselingSession` 情绪标签 | 深层情绪模式       | 模块5完成后自动接入 |

### Coze 配置

复用现有 `CozeService`，新增 `callChatOnce()` 非流式方法（情感分析不需要流式输出）。

情感分析 prompt 要求 Coze 返回六维分值 + 建议，JSON 格式：

```json
{
  "emotionType": "ANXIOUS",
  "intensity": 75,
  "dimensions": {
    "anxious": 75,
    "angry": 20,
    "sad": 40,
    "confused": 60,
    "calm": 15,
    "positive": 10
  },
  "keywords": ["压力", "焦虑", "不知所措"],
  "suggestion": "..."
}
```

`dimensions` 六维分值用于雷达图，`emotionType` 是主导情绪，`intensity` 是综合强度。`keywords` + `dimensions` 完整存入 `SentimentRecord.keywords`（JSON 字符串）。

```typescript
async checkAndUnlock(userId: number, achievementName: string) {
  const achievement = await prisma.achievement.findUnique({ where: { name: achievementName } });
  const user = await prisma.user.findUnique({ where: { id: userId } });
  const unlocked = JSON.parse(user.achievements || '[]');
  if (!unlocked.includes(achievement.id)) {
    unlocked.push(achievement.id);
    await prisma.user.update({
      where: { id: userId },
      data: {
        achievements: JSON.stringify(unlocked),
        exp: { increment: achievement.expReward },
        level: this.calcLevel(user.exp + achievement.expReward)
      }
    });
    // 推送通知
    await this.notificationsService.create({ userId, type: 'ACHIEVEMENT_UNLOCKED', ... });
  }
}
```

| GET  | /users/:id/achievements | 获取用户已解锁成就     | 登录 |
| GET  | /leaderboard            | 获取经验值排行榜 Top20 | 公开 |
